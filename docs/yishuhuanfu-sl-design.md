# SL 以薯换福设计方案

## 目标和游戏规则

在活动页完成领种、查价、出售、领提成和兑换，并看清每次自动成交的依据。自动卖薯以**当天实际拿到的福气币总量**为目标。先用自己的铺子计算日终结算，再判断把蜜薯卖给好友能多赚多少。

- 活动日期为 2026 年 11 月 25 日至 12 月 9 日。面板倒计时和后端可操作窗口使用服务端时间及活动结束时间。活动最后一天沿用普通日期的卖薯规则，服务端标记关闭后停止操作，结算结果以实际入账为准。
- 当天第一次进入活动可查看今日售价并领红薯种子。红薯种入普通农田，成熟收获时额外获得蜜薯。
- 自家铺子不限量。卖给好友按对方当日收购价结算，占用对方当日接收额度，好友获得分红。
- 每日首次成功分享铺子后有一次暴击涨价。同一铺子的当日报价只会上涨或维持，次日 0 点重新计算。铺子的剩余额度在日内仍会变少。页面区分「已发起分享」和「服务端确认涨价」。
- 每日 24 点，按自家当日最终收购价结算剩余蜜薯，福气币入账、蜜薯清零。页面把预计结算和已经确认入账分开显示。

## 活动页面

入口放在**活动 → 以薯换福**。已选 A，采用分标签页布局。页头固定显示库存、自家价、最高已查可售报价和自动化状态，下方分「今日操作」「好友比价」「记录」「兑换」。当前账号始终可见，手动操作和自动设置都在这个账号下生效。

| 区域 | 内容与操作 |
| --- | --- |
| 页头 | 当前账号和在线状态、库存、自家价、最高已查可售报价、自动化状态、活动结束时间和今日结算倒计时。提供「刷新状态」「自动化设置」。活动关闭后保留最后一次已确认的记录，并标明更新时间。 |
| 今日操作 | 红薯种子、蜜薯、福气币三个余额。显示「可领种／已领」「去种植」「可收／最早成熟时间」和「分享暴击待确认／已生效」。背包读取失败显示「未知」或明确标记上次余额。 |

| 记录与兑换 | 「记录」内分开显示「我卖出的蜜薯」「别人卖进我铺子」「日终结算」和「自动化历史」。兑换页展示盆栽·七色花弦、福气金豆礼包及其他目录商品的实时价格、限购和余额。 |

页面首屏优先显示自家收购价、当前最高**已查可卖价**和「预计比日终多赚」。例如「已查 20/86 家，最高已查可卖价 165，自家当前价 144」。有高报价却无额度的铺子可查阅，推荐出售时排除。移动端每家铺子展示成一张可点击的报价卡，出售确认保留账号、铺主、数量及总额。

## 完整手动操作

| 动作 | 操作步骤和反馈 |
| --- | --- |
| 查看今日价、领种子 | 打开活动自动读取当天状态。未领取时点「领取红薯种子」，按钮等待结果。成功后刷新种子余额和自家行情；已经领过显示服务端状态。 |
| 种植 | 点「去种植」打开普通农田，预选红薯种子。用户选择空闲地块，确认地块数和用种数量后种植。种子不足或已有作物时标明原因；有作物的地块保留。 |
| 收获 | 显示各批预计成熟时间，点「去收获」复用农场的成熟地块操作。收完分别显示红薯产量、实际新增蜜薯和可售余额；展示预计产量时标明为预估。 |
| 分享和核对暴击 | 点「分享铺子」展示可用的分享入口。由用户在 QQ／微信游戏里选好友或群聊并发送，返回后刷新自家报价。若平台能在面板内完成经验证的分享流程，可在这里提供该入口。服务端确认后显示「基础价 + 暴击 = 当前价」，每日只确认一次。 |
| 查好友铺子 | 点「重新比价」执行只读扫描，显示覆盖进度。可从报价表选铺，也可用已知 GID 查指定铺子。好友分享卡可在官方游戏内打开；面板只有在确认能从卡片可靠识别铺主后才提供粘贴入口。 |
| 卖给好友 | 选铺、输入数量或点「按可卖上限填入」，确认单同时显示当前报价、额度、预计总额、与留待日终的差额。提交前刷新当前报价和额度；两者变动时展示新条件供重新确认。成功显示服务端实际数量、单价和到账额。 |
| 手动批量出售 | 已选 B。在比价页点「生成出售计划」，按当前可售价格和额度建议各铺的卖出数量。用户可调整铺子和数量，在一次确认里查看每笔明细、总数量和预计收益。面板依次提交订单，后端逐笔核对实时价和额度。条件变动时暂停尚未执行的订单，列出已经成交的部分和新计划，等用户重新确认。保留每家铺子的单笔出售入口。 |
| 卖给自己 | 显示当前价、可售库存、预计到账及「留到 24 点按自家最终价结算」的区别。用户选择数量并确认，可用于需要立即拿福气币兑换的时候。 |
| 领提成、查记录 | 有可领提成时点领取，刷新待领提成和福气币。好友卖进我铺子的记录与我卖给好友的记录分开；后者由本面板保存已确认的出售回执，注明来源。 |
| 兑换 | 打开目录选商品和数量，确认总成本、限购和兑换后余额。从服务端校验余额和剩余额度，完成后刷新目录、余额和奖励回执。 |
| 查看 24 点结算 | 盘中显示预计入账。次日核对服务端记录或可归因的结算数据后显示「已入账」。只有库存下降或余额变化时显示「待核对」，同时保留前后状态供比对。 |

这些操作都以同一账号的实时状态为依据。出售、领种、领提成及兑换在等待回包期间禁用重复提交。超时或回包内容不一致时显示「结果待核对」，刷新余额和可读记录后再允许下一次操作。

## 自动卖薯逻辑

### 先算增收，再决定是否成交

`预计增收 = 计划卖出数量 ×（好友实时单价 − 自家结算基准价）`

优先领取种子生成当天行情。自家暴击已经由服务端确认时，用确认后的总价作基准。仍可能触发暴击时，默认等待确认；如用户确定今天不分享，可显式选择「用当前自家价作基准」，页上标明后续分享可能抬高基准。自家价、今日日期或库存无法确认时暂停自动成交。当前协议由服务器决定实际成交价，售前复查可以缩短报价差异的窗口，金额以成交回包为准。

**算例。** 背包有 1,000 个蜜薯，自家暴击后为 380。好友 A 出价 480、只剩 300 额度，B 出价 460、能接剩余 700。两家都达到 450 门槛，下表展示充分使用两家额度时的收益。

| 处置 | 福气币 |
| --- | ---: |
| 全部留到 24 点 | 380,000 |
| A 卖 300，B 卖 700 | 466,000 |
| 相对日终结算增收 | **86,000** |

如果 B 只出 440，高于自家价但低于 450，则只卖 A 的 300，剩下 700 留待日终，预计总计 410,000。该例假定自家最终价维持 380。

### 比价和执行顺序

1. **合并面板各账号的好友名单。** 已选 B，自动比价查当前账号及面板内其他账号已同步的好友。复用 404 的路径修复和损坏缓存隔离。合并后按 GID 去重，超出上限时分批轮转，显示已查覆盖率；以当前卖家能查到并确认可售的铺子为准。面板多账号并行比价可复用新鲜报价，已查额度由卖家下单前重新核对。手动查指定铺子独立于自动候选范围。
2. **区分定期扫价与下单复查。** 自动比价每 30 分钟扫一批，每批最多 200 家，保留有时间戳的报价表。查询按现有并发调度排队，合并后不超过 200 家可在一批内覆盖，超过时分批轮查。售前已选 C，复查本轮所有尚未由服务端确认暴击的铺子，发现涨价后按最新可售单价重新排序。已确认当日暴击的价格可用于候选排序。下每笔订单前仍复查最终目标铺子的当日价格、收购状态和可用额度。页面显示已查和未查家数，跨日清空旧榜单。
3. **按达标额度尽量卖。** 优先给单价最高的达标铺子分配数量，单笔取「剩余库存、对方最新额度」中的较小值。出价相同优先额度更多的一家，以减少交易笔数。逐笔核对服务端回执，更新库存与额度，再查下一家达标铺子。每笔留出请求间隔，到达本轮下单截止时剩余库存留待下一轮或日终结算。
4. **全天按高价门槛执行。** 已选收益策略 B「优先等高价」，固定最低售价为 **450 福气币／个**。好友实时单价达到 450 且高于自家结算基准价才可自动出售。结算临近时仍按该条件评估，达不到门槛的蜜薯留给游戏结算。
5. **日终收尾。** 每天于北京时间 23:55 停止发起新自动卖单，剩余蜜薯交给游戏按其日终规则处理。显示未售库存、预计入账及尚待确认的成交。最后一天沿用同一套时间与价格规则，服务端标记活动关闭后停止操作。

自动出售使用当天的后台报价，按价格从高到低选择达到最低报价的铺子，并在下单前核对目标报价和额度。每天从设置的时间起每半小时检查一次，支持重连补跑，23:55 停单。

### 什么时候等待

| 条件 | 自动处理和界面反馈 |
| --- | --- |
| 今日价格未生成、尚未确认分享暴击 | 先完成已启用的领种等准备动作，状态显示「等待自家基准」，保留蜜薯。 |
| 高价铺子已满或停止收购 | 当轮复核下一家，仍须满足价差门槛。无合格铺子时显示阈值、最佳可售报价和留存数量。 |
| 好友分享涨价或额度降低 | 涨价时重排候选，额度降低时重算可卖数量。等待确认模式中如果单价、目标或数量变动，展示新条件供确认。多账号候选来自同一店时按同一份剩余额度协调。 |
| 账号离线、切日、活动关闭、行情或库存过期 | 暂停交易。切日作废旧报价和当日计划，按新一日种子、行情及分享状态重新开始。 |
| 写入超时或回包不可信 | 暂停该账号本轮出售并标记待核对，刷新库存和福气币。余额无法解释时继续等待人工确认，避免重复卖出。 |

每笔保存「出售前自家价、铺主报价及核对时间、实际成交数量及单价、实际到账」。当天是否确实多赚以日终确认价复算。没有已验证的日终价时保留「按下单时基准估算」，避免把预测写进已确认收益。

### 逐轮历史

已选 B，保留本次活动的逐轮记录，按账号与游戏日期查看。每轮标明计划时间、实际执行时间、定时检查或重连补跑、报价覆盖和复核结果，以及成交、跳过、失败或结果待核对。展开后可看当时的自家价、450 门槛、候选报价与剩余额度、选店理由及实际成交。比如 23:30 没卖，能分清是账号掉线、最高可售报价未达 450，还是达标铺子已经收满。活动关闭后可继续查阅本次活动记录。

## 自动化设置

配置按账号保存。活动页可直接打开设置，助手设置中保留同一个入口。尚未配置过本活动的账号默认开启自动领种、种植、收获、分享流程、比价、按策略自动卖薯和自动领提成。按活动开放状态和账号实际能力执行，各项仍可单独调整。已有账号配置以保存值为准。

| 开关或模式 | 启用后的行为与设置 |
| --- | --- |
| 自动领取每日红薯种子 | 当服务端显示当天未领时执行一次，生成当天行情。跨日重新检查。 |
| 自动种植红薯 | 有空地时逐块按当前生长时间缩减估算红薯成熟时间。能在当日 23:30 和活动结束前成熟的空地优先种红薯，种到种子用完或合适空地用完为止。预计来不及的红薯种子留到下一个游戏日重新判断，剩余地块按日常策略处理。 |
| 自动收获活动红薯 | 只收已成熟的红薯，复用现有农场收获。自动种植和自动收获独立。已有的「自动收获」启用时由同一能力去重。 |
| 分享与确认暴击 | 平台能力已经验证且可用时，默认执行活动内分享流程并读回游戏状态。需要发给 QQ／微信好友或群聊时，提示用户在官方客户端完成。分享或上报后只按服务端更新确认暴击。 |
| 卖薯模式 | 「关闭卖薯与后台比价」「仅比价」「按策略自动卖」，新配置默认「按策略自动卖」。达到设定的开始时间后，按最低报价和复核规则成交。 |
| 自动卖薯参数 | 好友范围、扫价数量与间隔、最少库存数量、可选开始时间、高价门槛及单次出售量。界面显示当前门槛和报价是否达标，各参数的设置方式逐项确认。 |
| 自动领取提成 | 只有服务端显示可领且金额大于 0 时执行。显示本次金额和到账余额。 |

兑换保留手动确认，以便用户决定福气币优先购买的奖励。关闭自动卖薯后终止新的下单，已发请求继续核对结果；账号暂时离线时保存配置，连接恢复后显示实际生效状态。

### 红薯播种前的成熟时间判断

1. 普通农田出现空地时，读取游戏服务器时间、当天日期和该地块当前生效的生长时间缩减。红薯的基础时长来自作物生长阶段配置。土地缩减优先用服务端返回值，缺失时参考对应土地等级配置。预计时间只计可以确认的加成，时间或配置无法确认时等下次农场检查。
2. 每块地用预计播种时间加上折算后的生长时长。预计成熟严格早于当日北京时间 **23:30**，且早于活动结束，才自动种红薯。比如红薯基础时长为 12 小时，12:00 播种时，无缩时的地预计次日 00:00 成熟，有 20% 缩时的地预计当天 21:36 成熟，这轮只在有 20% 缩时的地种。这个算例按土地缩时估算，实际成熟时间以服务器状态为准。
3. 未赶上当日播种条件的种子留给次日。日常自动种植和背包优先种植也共用红薯成熟时间判断。活动页显示地块的预计成熟时间和「赶不上 23:30，种子留到次日」原因。手动播种时同样显示预估时间供用户决定。
4. 播种后以服务器返回的成熟状态更新预估。23:30 轮次启动时，如果自动收获已开启，先完成已成熟红薯的收获，再根据刷新后的蜜薯库存评估自动卖薯。

作物基础时长和土地缩时分别参考现有配置读取。 [作物配置读取](../core/src/config/gameConfig.ts) · [土地缩时读取](../core/src/services/farm/land-upgrade.ts)

## 实现与验收

- **页面和手动流程**复用 SL 活动中心和接口。覆盖当日初始、分享成功但涨价未确认、价格变化、额度变少、缺货、活动关闭和历史记录等状态。种植和收获先复用农场入口，并核对同一时间在不同加成地块上的播种结果、预计刚好 23:30 的边界、次日重新判断和最后一轮先收后卖。
- **只读比价和计划预览**先覆盖 404 的缓存路径、账号范围、失败隔离和过期处理。用固定报价验证 A 高价额度用完后是否选 B，B 低于自家价时是否留存。跨账号同时竞争同一好友额度时应重新估算后续计划。
- **启用自动出售前**验证每日 24 点的库存和福气币变动能否核对，以及各平台分享成功如何观察。测试覆盖活动关闭、切日、铺子分享后反超、剩余额度降低、离线、关闭开关、重复操作和写超时。
- **现场验证范围**先看只读计划和手动成交回执，再用少量蜜薯验证自动成交。明确标出活动记录能证实的结果和测算结果。

## 已确认的收益策略

**B．优先等高价。** 固定最低售价已确认为 **450 福气币／个**，好友实时报价必须同时高于自家结算基准价。全天维持同一条件，普通日期未达标或无额度的库存留给游戏按自家价结算。

**达标后尽量卖。** 按实时单价从高到低用足达标铺子的可收额度。还剩蜜薯时，再找下一家达标铺子。

**跨账号比价。** 合并面板内各账号已同步的好友名单，按 GID 去重，由当前卖家确认是否可售。

**比价间隔和批次上限。** 自动比价每 30 分钟扫一批，每批最多 200 家。成交前仍复查目标铺子的实时价和剩余额度。

**售前复查范围。** 复查本轮所有尚未确认暴击的铺子，按最新可售单价重新排序。

### 每日自动卖薯时段

未设置的账号从北京时间 **12:00** 起每半小时检查一次。已保存的账号沿用自选开始时间。开始前后台继续比价，开售后按每个账号的最低报价和售前复核规则决定是否成交。

如果账号掉线错过或中断了一轮，重连并同步好当前账号、当日行情及库存后，在 23:55 前补跑一轮。多轮错过合并为一次，接近下一轮时合并调度。已确认成交按最新库存和额度继续，结果待核对的卖单先查清。比如按默认时段运行时，23:30 掉线错过最后一轮，23:40 恢复即可补查。自 23:55 起停止发起新订单，剩余蜜薯由游戏在 24 点结算。出售时段和重连补跑按游戏服务器的北京时间执行。

**最后一天沿用每日规则。** 在服务端仍允许操作期间照常按门槛出售，剩余蜜薯交由游戏处理。
